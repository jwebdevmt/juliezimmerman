Engineering Case Study

Building an Integrated Sign Ordering Operation

The Problem

The signage operation had no shared CRM, vendor ordering process, work-in-progress view, or employee task visibility.

Constraints

Multiple functions needed to work together within infrastructure the team already understood.

Approach

I built a WordPress-based platform combining client records, vendor ordering, a Kanban board, stage lists, and employee work tracking.

Outcome

The full order lifecycle became visible in one system, from client request through vendor work and completion.

Looking Back

This is substantial enough to document both as a project and as a case study: the project describes the platform; the case study explains the operational system it replaced.

Perspectives

Julie: The value was integration. Five disconnected tools would have preserved five disconnected versions of the operation.

Nam: The platform turned an informal sequence into an inspectable operational model.

Jae: Client, vendor, stage, owner, status: one shared picture.

Engineering Principles

  • An operational system should make the whole workflow visible, not digitize isolated fragments.
